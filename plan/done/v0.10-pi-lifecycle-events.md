## 1. Name

`pi-lifecycle-events`

## 2. Scope

Add `recordLifecycleEvent` calls at PI delegate start/end, mapping PI session IDs to the CLI lifecycle event format established in v0.9.

This slice covers:

- `queued` lifecycle event before PI delegate execution
- `completed`/`failed` lifecycle event after PI delegate execution
- Per-target events for `delegate_agents_parallel`
- PI session ID mapping to lifecycle event format

This slice does NOT cover:

- Unifying PI local session tracking (events.jsonl, conversation.jsonl) with CLI lifecycle events
- Adding `AgentExecutionResult` return type to PI delegate functions
- Changing PI's local `deriveTaskType`/`sanitizeTaskDescription` wrappers

## 3. Design

### 3.1 delegate_agent Lifecycle Events

At `delegate_agent` start (before execution):

```typescript
const { recordLifecycleEvent } = await import("../scripts/session/m3-ops.mjs");
recordLifecycleEvent(repoRoot, delegateLifecycleId, {
  event: "queued",
  details: {
    task: effectiveTask.substring(0, 100),
    sourceAgent: runtime!.agent.name
  }
});
```

After execution completes:

```typescript
recordLifecycleEvent(repoRoot, delegateLifecycleId, {
  event: result.exitCode === 0 ? "completed" : "failed",
  result_code: result.exitCode,
  result_reason: result.exitCode === 0 ? "success" : "non-zero exit",
});
```

### 3.2 delegate_agents_parallel Lifecycle Events

For parallel delegates: emit `queued` per target before execution, `completed`/`failed` per target after.

Each target gets its own lifecycle event file using the same convention as serial delegates.

### 3.3 PI Session ID Mapping

PI already has `currentSessionId()` producing `<runtime>:<crew>:<session>` format. Use this as the `source_session` field in lifecycle events, consistent with CLI lifecycle event format.

### 3.4 Error Handling

All lifecycle event calls must be best-effort:

- Wrapped in try/catch — lifecycle event failure never blocks delegation.
- Errors logged but not propagated to the delegate result.
- Consistent with the evidence pipeline error handling pattern established in v0.9.

## 6. Risks

| Risk | Likelihood | Mitigation |
|------|-----------|------------|
| `m3-ops.mjs` not designed for concurrent multi-target events | Low | `recordLifecycleEvent` appends to JSONL — concurrent writes are safe per-target; verify in testing |
| Additional I/O in hot delegate path | Low | Lifecycle writes are sync file appends, sub-ms overhead; measure in testing |
| PI lifecycle events drift from CLI lifecycle event schema over time | Medium | Both paths use the same `recordLifecycleEvent` function — schema stays aligned |
| Dynamic import of `m3-ops.mjs` fails silently | Low | Same import pattern as evidence pipeline (delivered in v0.9); tested pattern |
